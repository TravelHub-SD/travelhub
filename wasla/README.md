# وصله — تطبيق توصيل الطلبات

تطبيق موبايل لتوصيل الطلبات (على فكرة تطبيقات مثل «طلبات») مبني بـ **React Native + Expo**،
مع **سيرفر حقيقي** وقاعدة بيانات ومصادقة — وليس بيانات وهمية داخل التطبيق.

الواجهة عربية بالكامل واتجاه RTL.

---

## المحتويات

```
wasla/
├── apps/
│   ├── server/     سيرفر Express + Prisma + SQLite + JWT
│   └── mobile/     تطبيق Expo (React Native + TypeScript)
└── README.md
```

---

## التشغيل السريع

### 1) السيرفر

```bash
cd apps/server
npm install
cp .env.example .env
npm run db:push     # إنشاء قاعدة البيانات
npm run db:seed     # تعبئة متاجر وأصناف ومستخدم تجريبي
npm run dev         # يعمل على http://localhost:4000
```

للتأكد أنه يعمل:

```bash
curl http://localhost:4000/health
```

### 2) التطبيق

في نافذة طرفية ثانية:

```bash
cd apps/mobile
npm install
npm start
```

ثم افتح تطبيق **Expo Go** على جوالك وامسح رمز QR الظاهر في الطرفية.

> **مهم:** يجب أن يكون الجوال والكمبيوتر على **نفس شبكة الواي فاي**.
> التطبيق يستنتج عنوان السيرفر من عنوان Metro تلقائياً، فلا تحتاج لتعديل أي شيء يدوياً.

## ماذا يفعل التطبيق

| الشاشة | الوظيفة |
| --- | --- |
| تسجيل الدخول / إنشاء حساب | مصادقة بالهاتف وكلمة المرور، الجلسة محفوظة ومشفّرة |
| الرئيسية | العنوان الافتراضي، التصنيفات، الأكثر طلباً، كل المتاجر |
| البحث | بحث فوري عن متجر أو منطقة (مع تأخير ذكي) |
| صفحة المتجر | القائمة مقسّمة لأقسام، التقييم، رسوم التوصيل، الحد الأدنى |
| السلة | تعديل الكميات، ملخص الأسعار، تنبيه الحد الأدنى |
| تأكيد الطلب | اختيار العنوان، طريقة الدفع، ملاحظات للمندوب |
| تتبع الطلب | خط زمني حي لمراحل الطلب، مع تحديث تلقائي |
| طلباتي | الطلبات الجارية والسابقة |
| العناوين | إضافة/حذف/تعيين عنوان افتراضي |
| حسابي | بيانات المستخدم وتسجيل الخروج |

### دورة حياة الطلب

```
PENDING → CONFIRMED → PREPARING → ON_THE_WAY → DELIVERED
                  ↘ CANCELLED (يمكن الإلغاء قبل بدء التجهيز فقط)
```

السيرفر يحتوي **محاكياً** ينقل الطلب تلقائياً بين المراحل كل 25 ثانية، لتظهر شاشة
التتبع كما ستعمل في الإنتاج. في نظام حقيقي تأتي هذه التحديثات من تطبيق المتجر والمندوب.
لتعطيله: `ORDER_SIMULATOR=off`.

## واجهة السيرفر (API)

| الطريقة | المسار | الوصف | يحتاج توكن |
| --- | --- | --- | --- |
| POST | `/api/auth/register` | إنشاء حساب | ✗ |
| POST | `/api/auth/login` | تسجيل الدخول | ✗ |
| GET | `/api/auth/me` | بيانات المستخدم | ✓ |
| PATCH | `/api/auth/me` | تعديل الاسم/البريد | ✓ |
| GET | `/api/categories` | التصنيفات | ✗ |
| GET | `/api/stores` | المتاجر (`?category=` `?q=` `?featured=`) | ✗ |
| GET | `/api/stores/:slug` | تفاصيل متجر مع القائمة | ✗ |
| GET | `/api/popular-items` | الأصناف الأكثر طلباً | ✗ |
| GET/POST | `/api/addresses` | عرض/إضافة عنوان | ✓ |
| PATCH/DELETE | `/api/addresses/:id` | تعديل/حذف عنوان | ✓ |
| POST | `/api/orders` | إنشاء طلب | ✓ |
| GET | `/api/orders` | طلباتي | ✓ |
| GET | `/api/orders/:id` | تفاصيل طلب + خط زمني | ✓ |
| POST | `/api/orders/:id/cancel` | إلغاء الطلب | ✓ |
| POST | `/api/orders/:id/advance` | تقديم المرحلة (للعرض) | ✓ |
| POST | `/api/orders/:id/review` | تقييم بعد التوصيل | ✓ |

كل الأخطاء تعود بالشكل `{ "error": { "message": "...", "code": "..." } }` برسائل عربية جاهزة للعرض.

## ملاحظات تقنية مهمة

- **الأسعار تُخزَّن بالقرش** (أصغر وحدة) كأعداد صحيحة، تفادياً لأخطاء الفاصلة العائمة.
  `250000` تعني `2,500 ج.س`. التحويل يحدث عند العرض فقط.
- **السيرفر لا يثق بأسعار العميل.** عند إنشاء الطلب تُقرأ الأسعار من قاعدة البيانات
  ويُعاد حساب الإجمالي، ويُرفض أي صنف لا يخصّ المتجر المطلوب.
- **العزل بين المستخدمين مُختبَر**: لا يمكن لمستخدم قراءة أو تعديل طلبات وعناوين غيره.
- **الطلب من متجر واحد** في السلة، مع طلب تأكيد قبل استبدال سلة متجر آخر.
- **الاتجاه RTL** مبني في الأنماط صراحةً بدل `I18nManager.forceRTL`، لأن الأخير
  يتطلب إعادة تشغيل التطبيق ليأخذ مفعوله.
- **الخط Cairo** يُحمَّل محلياً من `@expo-google-fonts/cairo` (لا يحتاج إنترنت وقت التشغيل).
  على أندرويد لا يعمل `fontWeight` مع الخطوط المخصّصة، لذلك **لا نستعمل `fontWeight`
  إطلاقاً** — بل عائلة مستقلة لكل وزن عبر `font` في `src/theme.ts`:

  ```ts
  import { font } from '@/theme';
  title: { fontSize: 17, lineHeight: 26, fontFamily: font.extrabold }
  ```

  وكل نمط نصّي يحتاج `lineHeight ≈ 1.5 × fontSize`، لأن Cairo أطول من خط النظام
  ويحتاج مساحة للتشكيل — بدونه تُقصّ الحروف. (لا تضع `lineHeight` على `TextInput`،
  فهو يسبب اختلال محاذاة على أندرويد.)
- **العملة** افتراضياً الجنيه السوداني (`ج.س`) وتُضبط من `CURRENCY` في `.env`
  ومن `apps/mobile/src/format.ts`.

### الشعار

الشعار **متجه** (SVG) وليس صورة، فيظهر حاداً في كل الأحجام ويُعاد تلوينه حسب الخلفية:

- `src/components/WaslaLogo.tsx` — للاستعمال داخل التطبيق (`WaslaMark` للعلامة وحدها)
- `assets/logo/wasla-mark.svg` — المصدر الذي تُولَّد منه الأيقونات

الشكل الحالي **إعادة بناء تقريبية** من ملف الهوية. لاستبداله بالشعار الأصلي:

```bash
# 1) ضع ملف SVG الرسمي مكان الملف الحالي (بنفس الاسم والمسار)
#    استعمل #F4661B للبرتقالي و #FFFFFF للأبيض حتى تعمل إعادة التلوين
cp ~/wasla-logo.svg apps/mobile/assets/logo/wasla-mark.svg

# 2) ولّد كل الأيقونات وشاشة البداية دفعة واحدة
cd apps/mobile && node scripts/generate-icons.mjs
```

ثم انسخ نفس المسارات إلى `WaslaLogo.tsx` ليتطابق ما يظهر داخل التطبيق مع الأيقونات.

## ما تم اختباره

- السيرفر: 30+ حالة عبر كل المسارات (مصادقة، صلاحيات، حدود الطلب، متجر مغلق،
  إعادة حساب التقييم، منع التقييم المكرر).
- التطبيق: يبني بنجاح لـ Android، ويمرّ اختبار متصفح كامل من تسجيل الدخول
  حتى إنشاء طلب وتتبّع مراحله والتقييم.

## قبل النشر للإنتاج

1. غيّر `JWT_SECRET` في `.env` (السيرفر يرفض الإقلاع بالقيمة الافتراضية).
2. حوّل Prisma من SQLite إلى PostgreSQL في `apps/server/prisma/schema.prisma`.
3. أضف تحقق الهاتف عبر OTP بدل كلمة المرور فقط.
4. اربط بوابة دفع حقيقية (حالياً `CARD` و `WALLET` مسجّلتان كنيّة دفع فقط).
5. استبدل المحاكي بتطبيقي المتجر والمندوب، وحوّل التتبع إلى WebSocket بدل الاستعلام الدوري.
